# 后续优化内容 Roadmap（可直接拆分为迭代任务）

本文档将“内容获取与更新 / 搜索与发现 / 账号与多端同步 / 分享与增长 / 性能&SEO&工程化”整理为可落地的迭代路线图。默认按“先把核心闭环跑通，再做增长与工程化”的顺序安排。

## 0. 现状梳理（当前版本能力）

- 数据来源：
  - 站内书：前端 mock 数据（`src/mock/data`）。
  - 本地书：txt 导入 + IndexedDB 存储章节（`chapters_${bookId}`）。
- 阅读侧：
  - 段落级书签、高亮&笔记（段落内范围）、目录搜索与缓存、阅读进度段落记忆、阅读时长统计。
- 缓存：
  - 章节缓存：`cache_chapters_${bookId}`（IndexedDB）。

## 1. 内容获取与更新（数据源、增量、提醒）

### 1.1 数据源一期：最小“后台 + API + 管理”

- **目标**：替换 mock，为前端提供“真实可更新书籍&章节”。
- **核心实体（建议）**：
  - Book：id、title、author、coverUrl、category、status（连载/完结）、wordCount、latestChapterId、updatedAt
  - Chapter：id、bookId、index、title、content、wordCount、updatedAt
- **API（建议）**：
  - `GET /books?query&category&status&sort&page`
  - `GET /books/:id`
  - `GET /books/:id/chapters?sinceChapterId|sinceUpdatedAt`（增量）
  - `GET /books/:id/chapters/:chapterId`
- **后台录入方式（阶段性）**：
  - v1：管理后台手工录入/导入（Markdown/TXT 批量导入）。
  - v2：爬虫/第三方源适配（需合规评估）。

### 1.2 章节增量更新（前端拉取）

- **策略**：
  - 以 `updatedAt` 或 `chapterIndex` 作为增量依据。
  - 前端在书籍详情/书架入口触发检查更新，并落地到本地缓存。
- **数据落地**：
  - 本地缓存最新章节列表 + 章节内容（IndexedDB）。
  - 维护 `bookSyncStateById`（lastSyncAt、latestKnownChapterId、etag 等）。

### 1.3 更新提醒（站内消息/邮件/推送）

- **站内更新订阅**：
  - 用户收藏/订阅某本书。
  - 后台检测到新章 → 生成通知 → 前端拉取展示。
- **提醒渠道阶段**：
  - v1：站内消息（消息中心+角标）
  - v2：邮件（用户可配置开关）
  - v3：Web Push / App Push（与 PWA 结合）

### 1.4 更新订阅体验（书架高亮/角标、更新时间线）

- 书架卡片：
  - 新章角标（例如 `+3`）
  - 最近更新时间显示（x 分钟前）
- 更新时间线：
  - 聚合展示订阅书籍的更新流（按时间排序）
  - 支持筛选（仅未读更新）

### 1.5 本地导入升级

- **epub（可选）**：
  - v1：支持导入 epub 并解析目录（可先用纯前端解析库，或后端转换）。
- **章节识别规则更丰富**：
  - 增加规则选择：按“第X章”、按“卷/部”、按“自定义正则”、按“字数切分”。
  - 保存书籍导入时使用的规则，避免后续重切分导致书签/进度失效。
- **导入后编辑元信息**：
  - 可编辑书名/作者/封面（封面可上传或本地选图）
  - 元信息写入本地书 bookInfo 并同步到书架展示

## 2. 搜索与发现

### 2.1 搜索页增强

- 搜索历史：
  - 记录关键词（去重、上限、清空）
- 热搜：
  - 后台返回热词列表（可按分类/时间段）
- 联想词：
  - 输入时 debounce 请求 `GET /suggest?q=...`
- 筛选：
  - 分类/状态/字数区间
- 无结果推荐：
  - 显示“同类热门/你可能喜欢”

### 2.2 推荐算法基础版（不复杂但有效）

- 数据输入：
  - 读过（阅读历史）
  - 收藏（书架/订阅）
  - 同类热门（分类榜单）
- 推荐策略（阶段）：
  - v1：基于分类相似度 + 热度排序（最易落地）
  - v2：加入协同过滤的简化版（同收藏用户也收藏了什么）
  - v3：加入阅读时长/完读率权重
- 前端呈现：
  - 首页“为你推荐”
  - 书籍详情“你可能还喜欢”

### 2.3 榜单细分

- 榜单类型：
  - 新书榜 / 完结榜 / 高分榜 / 最近更新榜
- 支持按分类切换：
  - 玄幻/都市/科幻...
- 后端接口建议：
  - `GET /ranks?type&category&page`

## 3. 账号与多端同步

### 3.1 书架/阅读进度云同步（核心）

- 同步对象（建议一期就做全）：
  - 书架（收藏/订阅）
  - 阅读进度（章节 + 段落）
  - 书签
  - 高亮&笔记
  - 阅读设置（可选）
- 同步策略：
  - v1：登录后全量拉取 + 本地覆盖（简单）
  - v2：增量同步 + 冲突解决（多端并发）
- 冲突策略（建议）：
  - 进度：以 updatedAt 较新者为准
  - 书签/高亮：按 id 合并，删除用 tombstone 标记

### 3.2 数据迁移：本地导入书同步到云端/仅本机

- 在导入/书籍详情提供选项：
  - 仅本机
  - 同步到云端（上传书元信息 + 章节内容或仅上传元信息）
- 注意：
  - 上传全文可能涉及版权与存储成本，需要明确产品策略。

## 4. 分享与增长

### 4.1 分享落地页

- 分享链接支持：
  - 书籍详情
  - 指定章节
- 技术点：
  - 路由识别 `/#/book/:id` 或 `/#/read/:bookId/:chapterId`
  - 落地页加载后自动拉取对应数据

### 4.2 海报图生成（书名+封面+二维码）

- v1：前端 canvas 生成（简单）
- v2：后端生成（更稳定，便于埋点）

### 4.3 导出能力增强

- 导出范围：
  - 当前章 / 后 N 章 / 全书
- 导出格式：
  - HTML（已有）
  - epub/pdf（可选，后续做）

## 5. 性能 / SEO / 工程化

### 5.1 PWA 离线阅读

- manifest + service worker
- 缓存策略：
  - 静态资源 cache-first
  - 章节内容 stale-while-revalidate
- 支持“添加到桌面”
- 断网可读（依赖章节缓存完善）

### 5.2 SEO（书籍详情页 meta）

- 对书籍详情页生成：
  - title/description
  - og:title/og:description/og:image
- 若未来上 SSR/SSG（Next.js 等），SEO 效果更明显；纯 SPA 也能改善分享卡片与部分爬虫收录。

### 5.3 错误监控

- 接入前端错误上报（Sentry 同类）：
  - JS runtime error
  - API error
  - 关键用户行为埋点（可选）
- 输出：
  - 版本号、用户 id、bookId/chapterId、stacktrace、环境信息

## 6. 建议开发顺序（按投入产出比）

1) 真实数据源 + 增量更新（先解决“内容从哪来”和“如何更新”）
2) 更新订阅 + 书架角标 + 更新时间线（建立留存闭环）
3) 搜索增强 + 榜单细分（获取）
4) 云同步（增长后再补齐多端体验，但移动端很关键可提前）
5) PWA 离线（与缓存体系合并推进）
6) 分享海报与导出增强（增长和工具链）
7) 错误监控与 SEO（工程化长期收益）
